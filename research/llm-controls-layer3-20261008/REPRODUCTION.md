# 研究方法与复现导航

本研究考察既有中文只读助手中，开放语言解释、协议合规、有限执行权、审查和范围确认分别产生什么结果。青野与图书馆来自同一仓库和开发者；本地产品回放使用单实例、固定Clock及H2夹具。模型API采集、归档核对、原生回放与新的完整复刻是不同步骤。以下进度截至2026年10月8日。

研究由本科生在个人项目条件下开展，范围既受可用资源约束，也用于隔离实验变量。贡献定位为可复核的工程反例、受控比较与有边界的设计认识；不覆盖生产级微服务、分布式事务或资金类操作，不将两个同源系统视为独立组织复现。

## 术语与判定

| 概念 | 本研究如何观察 | 不能由它推出什么 |
|---|---|---|
| 语义正确 | 计划保留冻结题目中仍有效的动作、对象与条件，按该层oracle评分 | 执行者标签不等于真实用户原意；intent标签不匹配也不自动证明事实答错 |
| 协议合格 | 原始输出完整满足对应系统字段、类型和枚举；不补字段、不删除条件 | 结构合格不证明计划理解正确或允许执行 |
| 执行资格 | 本地能力合同、会话主体、参数与对象等约束允许该计划执行；需要确认时尚不能读取个人记录 | 合法查询不证明它是用户要的查询 |
| 事实正确 | 查询参数、返回记录及本地回答与被读取的数据记录一致 | 当前数据库记录不自动证明真实世界完整性、历史覆盖或未来履约 |
| 范围确认 | 用户可见实际查询范围；确认绑定同一主体、会话和计划，并在有效期内消费 | 模拟确认不证明真人看懂或发现遗漏；同一计划不等于冻结结果快照 |
| 用户原意 | 用户希望完成的任务；本实验用执行者事前oracle作为有限代理 | 模型一致、审查通过、本地允许及确认点击均不是用户原意的证明 |
| 任务满足 | 在相应评分口径下，输出实际满足明确对象和条件；与协议及权限另记 | 表未变化或没有越权不能替代任务满足评分 |

语义、格式、资格、事实、范围与可用性分别记账。错误QUERY被拦住可以是安全收束，不能记作恢复了正确答案；正确CLARIFY被再次判CLARIFY不算正确QUERY误杀。重复次数不等于独立题目或用户数，推断保留题/题族聚类。

## 四层控制的职责

| 层 | 谁负责 | 决定什么 |
|---|---|---|
| 入口资格 | 本地范围守卫 | 输入是否属于该入口；明显越权、写操作等是否拒绝进入规划 |
| 语义计划 | 模型与严格协议解析 | 提出一个有限QUERY、CLARIFY或REJECT候选；没有指定主体、SQL或任意动作的权力 |
| 执行资格 | 本地系统 | 当前入口、会话主体及能力能否执行该计划；未知对象、未支持条件不能靠猜测放宽 |
| 事实返回 | 固定查询与本地渲染 | 从允许的数据路径取得记录并展示；模型不生成库存、位置或借阅事实 |

“四层”描述责任划分，不是四个同类过滤器，也不意味着形式证明了所有输入安全。开放语言产生的个人查询计划需要先展示范围；完整标准命令按原产品合同处理。范围确认是执行控制点，让用户能接受或纠正解释，不替本地授予额外查询权，也不证明真人一定识别误解。

## 为什么从只读开始

在仅允许公开信息及当前会话个人记录的前提下，本研究主动减少模型误解导致的业务状态变更，把测量先集中在查什么、查谁、哪个对象、哪个时间和哪些条件。模型不能创建、修改或删除业务记录；这不意味着系统没有确认状态、日志等内部状态变化，也不意味着只读数据泄露可逆。

只读仍可能读错主体、漏条件、混淆实体、扩大推荐范围，或用当前状态代答历史和未来问题。这些问题分别属于权限、语义、事实来源或任务满足，不能以“只是查询”忽略。选择只读是本实验的控制条件，不是所有CRUD操作总损失的普遍排序；写操作的幂等、版本、确认及恢复合同属于后续研究。

以假设的购物助手为例，“帮我清空购物车”在不同语境中可能指删除条目、结算商品，也可能出现在试探、玩笑或引用中。识别出一个动作候选，不等于该入口支持该动作、当前主体有权执行或用户已作出具体执行承诺。此例用于解释研究动机，没有测试淘宝或其他平台，也不主张某一种解释总是正确。

若未来提供删除或交易能力，应先澄清歧义，检查入口能力与权限，再展示实际对象、操作及后果，通过可信交互绑定确认；模型声称“用户已同意”不能替代该记录。用户确认也不扩大原有权限，执行时仍需按产品合同重检资格及必要状态。这个流程可以留下程序意义上的授权证据，不能证明用户一定理解后果或没有误点。当前两套助手仍不提供这些写操作；写操作与真人承诺的效果不由本轮只读实验取得资格。

## 相关工作定位

[ToolGate](https://aclanthology.org/2026.findings-acl.470/)用前置/后置条件约束工具调用与状态提交；[ToolSafe](https://aclanthology.org/2026.findings-acl.1850/)研究步骤级工具安全检测及反馈。它们与执行约束相关，本研究没有实现或比较其完整框架，不能从不同职责名称推出性能或安全性优越。

[Design Patterns for Securing LLM Agents against Prompt Injections](https://arxiv.org/html/2506.08837v1)的action-selector模式已讨论从自然语言选择预定义动作及模板查询。[CaMeL](https://arxiv.org/abs/2503.18813)也研究能力约束及控制/数据流隔离。因此有限动作、隔离解释与执行不能声称是本研究首次提出。“四道门”不是独创性的计数依据。

本研究的定位是两个既有中文只读系统中的实证分解：把开放语义错误、严格协议、原生资格、一致性、自审/互审、范围确认、事实结果及代价分开观察，并保留失败、混杂和无法识别的结果。上述引用用于说明研究联系，不构成系统性全文综述或与这些方法的对照实验。

## 第一阶段与最终冻结复验

第一阶段完成计划内的非人工机制探索与控制检查，保留所有请求身份、传输状态、模型ID、原始响应、usage与延迟。测量错误如需修复，保留首败并版本化；不回写旧证据。金额继续控制原累计预算，暂不作为论文主结果。day1属于本阶段的真实跨日检查；后续控制已另在新查询包冻结执行，不能混进既有封印。

第一阶段收口后，根据研究问题冻结最终完整矩阵，明确核心对照与探索扩展，不按前期结果好坏挑组选题。第二阶段用新请求身份和新输出坐标全量复验纳入的组，不再调整方法、prompt、oracle、参数、评分器或夹具；支持、推翻和无法识别都保留。若测量器失效或输入改变，先停并保留候选，再按需要另立版本，不能用局部好结果替代整轮复验。

最终复验同时核对主要研究结果和资源开销。资源主指标为已发起/成功/超时/未知请求数、已知输入/输出token、usage缺失、单题/策略增量token及延迟。请求身份是客户端记录，不自动等于供应商计费次数；未知usage不填零，已知token合计不冒充完整总量。token不是FLOPs，各模型分别报告。共享提案的策略逻辑使用量与实际采集量分开，单次API实测P50/P95与策略逻辑时延分开。同一执行者重跑已见题集仍不冒充独立外部验证。
