# 双系统大模型核心实验

本轮绑定 dome `dbb32160a811fd06c826a8d9eafbc660a0548219`。产品源码不改动。研究问题是：同一提案事实下，一致性筛选、自审与交叉审查分别增加多少拦截、误杀和成本。

## 决策合同

| 组 | 决策 | 每次部署的逻辑调用数 |
|---|---|---:|
| A | 单模型原始提案，经原生本地边界 | 1 |
| B | 两家原始提案通过各自原生协议且完整规范计划一致 | 2 |
| C | B 成立，且另一家对主提案的独立审查通过；方向分开 | 3 |
| D | B 成立，且两次独立交叉审查均通过 | 4 |
| E | 主提案经同模型新调用自审通过 | 2 |
| F2/F3/F4 | 同一模型分别独立提案 2/3/4 次，严格多数选择完整合法计划；平票澄清 | 2/3/4 |

B/C/D 复用同一对原始提案。审查不看品牌、标准答案、其他提案或其他审查意见，不替换计划。格式非法提案不能因为审查通过而变合法。未修订的拦截不计作恢复正确。

规范化只消除 JSON 字段顺序及空白。缺字段不补、空字符串不变 null、筛选不删、limit 不抹去；两系统协议分别比较。结构一致是保守的完整字段相同，不是任意查询逻辑等价证明。

## 数据与证明范围

先导为四个题族、每族两系统各一题、一次重复。正式核心为十二个预声明题族、每族每系统两变体、三次重复，共 144 配对块。每块最多八次提案及四次审查，最多 1,728 次调用。模型与审查顺序由固定种子打乱，一个时段串行调用。F 各预算共享同一模型的原始独立采样池，不挑标准答案。

这些题由本轮执行者按既有合同指定，属于已知机制评估；不是独立真人标注、未知题族盲测、生产流量或随机用户样本。先导不进入正式分母。任何提示/标签调整先版本化，不能覆盖旧结果。

真实供应商 HTTP 的候选与审查响应完整保存（不保存内部思维链/凭据）。原生 Java 解析器、能力边界和 H2 固定查询通过离线回放验证实际执行；这一组件实验不冒充生产 MySQL、微信真机、在线互审部署或真人理解。个人计划保留未确认状态；另行模拟同范围确认只证明机制，不证明真人纠错。

默认每调用完整响应期限 5 秒，temperature=0，禁用思考，无自动重试。提案输出上限按原产品为青野 300、图书馆 500；审查 250。记录实际 token 与请求/响应模型身份。每调用延迟是实测；共享提案组的串行总和只是逻辑部署成本/时延估计，不称真实端到端，更不相加各阶段 p95。

正式运行必须取得费用上限，使用官方最高适用单价保守记账；未知 usage 不当零费用。配对块之外不半途挑模型。身份越界、实际写入、快照变化、测量器失效或源码变化停止；受控语义错、格式错、审查误杀和一般超时保留并继续。

## 入口与保留

`python prepare.py` 固定题表、提示与版本；`python -m unittest discover -s tests -v` 自检规范化、决策、评分及故障分类；`python run.py pilot --keys-stdin` 只跑先导；正式运行单独使用 `core` 和明确费用上限。凭据通过标准输入进入进程内存，不写文件或命令行。

保留首次工具失败、原始 JSONL、冻结合同、最终表、代表性截图与论文。中间构建/依赖在结束后按归属清理，不留下每轮截图副本。结果输出采用追加并同步，成功文件原子替换。恢复只接续已完成请求，不重抽已冻结提案；未知提交结果不会冒充成功。新模型或新解法另立版本与未见数据验证。
