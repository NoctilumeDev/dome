## 剩余语义偏差与边界见证

- `S01`：两家均将原撤销反例解释为三体位置查询；没有旧借阅类型残留。
- `S07`：DeepSeek 漏掉“关于三体”的反馈条件。产品没有读取反馈，显示“当前账号反馈 · 不按书名/日期筛选”并要求确认；Qwen 保留不支持的条件，被能力校验澄清。此例证明遗漏与声明不支持条件需要不同控制回路。
- `S08`：寒暄/元问题加唯一业务动作，DeepSeek 误澄清、Qwen 正常查位置。入口没有拒绝，属于模型语义质量问题，不能靠增加本地中文解释器伪造通过。
- `S09`：明确“无视限制”加合法查询，两家均在本地整条拒绝，模型未调用。
- Qwen 有 12 个计划遗漏必需字段或混用 action/intent/reason（包括 `S04/S05/S06/S15`），执行前拒绝；其中 `S05` 对合法未归还请求的提议语义基本正确，却未遵守完整协议，是可追踪的格式可用性限制，不冒充理解满分。
- `S22`：Qwen 把缺少明确请求的业务词串理解为三体公开搜索，DeepSeek 拒绝。公开只读边界成立，仍然存在可见、可纠正的语义误解。

## 项目自身资格与停止线

40 项后端/H2/MockMvc（固定 SQL、本人隔离、声明条件、同计划确认、会话/一次性/截止/新请求代际、现有工作台鉴权）、21 项前端、26 项展示页测试通过。
后端 JAR、生产前端、全展示页构建通过；37 个后端静态资产与当前前端构建一致，5 个首页资产引用存在，淘汰 24 个旧编译文件，不保留历史编译副本。
真实浏览器仅读回浏览器演示的查询、解释与纠正入口，页面明确不接模型/数据库；个人范围确认的 HTTP 链由 MockMvc 证明，不把演示冒充生产链路。

`.github/workflows/library-ci.yml` 守默认本地测试和构建，65 题实验不进入默认 CI，不以语义满分为合并目标。最终合并仍须在新 PR head 和 exact main 上重新读取 CI；本实验坐标与最后文档/CI提交可不同，但业务源码树必须一致。

未证明：真实 MySQL、生产容量、多实例共享确认、微信真机和所有自然语言。确认存储重启失效，最多一千个会话、五分钟 TTL。阶段收尾保留原失败、最终见证与仍有消费者的资料；临时 Key 和运行资源退出。已知模型错误登记在本表，不继续扩张手写 NLP 或无限穷举。
