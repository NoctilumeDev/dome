# 第四周：把一条报修送给 Java

上周最后问，浏览器能不能把宿舍号和报修内容一起交给 Java？

试一下。

代码已经改好了。[重新运行](第00周.md)，打开：

<http://localhost:8080/repair?room=5-203&content=门锁坏了>

浏览器里会出现：

```json
{
  "id": null,
  "room": "5-203",
  "content": "门锁坏了"
}
```

这张报修单不是 Java 提前填好的。宿舍号和报修内容，都是浏览器刚刚带过来的。

把 `5-203` 和“门锁坏了”换掉，再打开一次。Java 代码不用改，回来的一整条报修也跟着变。

这周 `Repair.java` 没改。`RepairController.java` 现在是这样：

```java
package com.example.repair;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController // Spring 得先知道，这里也能回话
public class RepairController {

    @GetMapping("/repair") // 找 /repair 的，交给下面这段
    public Repair repair(
            @RequestParam("room") String room,
            @RequestParam("content") String content) {
        Repair repair = new Repair(); // 先拿一张空的报修单
        repair.setRoom(room); // 把浏览器带来的宿舍号填进去
        repair.setContent(content); // 再填上报修内容
        return repair; // 整张报修单交回去
    }
}
```

`@RequestParam` 是第二周见过的那个东西。那时只接一个 `name`，这次一个接 `room`，一个接 `content`。

接住以后，先拿一张空的报修单，再把宿舍号和报修内容填进去。编号没人带来，也还没有人填，所以还是 `null`。

最后的 `return` 没变，整张报修单又回到了浏览器。

不过，浏览器每次来，都得把宿舍号和报修内容重新带一遍。Java 只是接住，又交了回来。

它能不能把这条报修留下，等我们下次再来时还能找得到？
