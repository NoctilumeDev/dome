# 第三周：把一条报修交给浏览器

上周最后说，一个名字留一个位置就够了，可一条报修还有宿舍号、报修内容，后面还会有编号。

总得给它们各留一个位置。

代码已经添好了。[重新运行](第00周.md)，打开：

<http://localhost:8080/repair>

浏览器里会出现：

```json
{
  "id": null,
  "room": "3-412",
  "content": "水龙头漏水"
}
```

三样东西没挤在一句话里。编号是编号，宿舍号是宿舍号，坏了什么也单独放着。

第二周的 `HelloController.java` 没改。这周只多了两个文件。

先看 `Repair.java`：

```java
package com.example.repair;

public class Repair {

    private Long id; // 编号放这里
    private String room; // 宿舍号放这里
    private String content; // 坏了什么放这里

    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getRoom() {
        return room;
    }

    public void setRoom(String room) {
        this.room = room;
    }

    public String getContent() {
        return content;
    }

    public void setContent(String content) {
        this.content = content;
    }
}
```

上面三行，就是给编号、宿舍号和报修内容留的位置。

下面的 `get...`、`set...` 现在看着有点长。先看名字：`setRoom` 是往 `room` 里放，`getRoom` 是从 `room` 里拿。它们为什么要这样写，今天先放着。

再看 `RepairController.java`：

```java
package com.example.repair;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController // Spring 得先知道，这里也能回话
public class RepairController {

    @GetMapping("/repair") // 找 /repair 的，交给下面这段
    public Repair repair() {
        Repair repair = new Repair(); // 先拿一张空的报修单
        repair.setRoom("3-412"); // 填上宿舍号
        repair.setContent("水龙头漏水"); // 填上坏了什么
        return repair; // 这次交出去的是整张报修单
    }
}
```

`new Repair()` 先拿来一张空的报修单。下面两行填了宿舍号和报修内容，编号没有填，所以刚才看到的是 `null`。

最后还是 `return`。只不过前两周交出去的是一句话，这次交出去的是一整条报修。

Java 里没写大括号，也没写那些双引号，浏览器里却是那副样子。这个样子叫 JSON，是 Spring 帮我们变出来的。

先把宿舍号或者报修内容换掉，重新运行，再看看浏览器里哪一处跟着变了。

不过，这张报修单还是 Java 自己填的。真正来报修的人还在浏览器那头。

下周让他填。
