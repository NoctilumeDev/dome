# 第五周：让 MySQL 记住

上周最后问，Java 能不能把一条报修留下，等我们下次再来时还能找得到？

先给它找个能放东西的地方。这个地方叫 MySQL，那 MySQL 是怎么放东西的呢？我们往下慢慢探索。

这周 Java 代码不动。打开 MySQL 里写 SQL 的地方，我们先放一条进去：

```sql
CREATE DATABASE after_class DEFAULT CHARACTER SET utf8mb4;

USE after_class;

CREATE TABLE repair (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    room VARCHAR(20),
    content VARCHAR(200)
);

INSERT INTO repair (room, content)
VALUES ('3-412', '水龙头漏水');

SELECT * FROM repair;
```

最后一句会把刚才那条报修拿出来：

| id | room | content |
| --- | --- | --- |
| 1 | 3-412 | 水龙头漏水 |

我们没有填 `id`，MySQL 自己给了一个 `1`。下一条会是 `2`，不会和前面那条挤在一起。

现在把写 SQL 的窗口关掉，再开一个新的，只写：

```sql
USE after_class;

SELECT * FROM repair;
```

那条报修还在。

前几周，Java 接住东西，交回来，也就没了。这次窗口都关过一次，MySQL 还是记得。

既然留下了，再动它一下。先加一条新的：

```sql
INSERT INTO repair (room, content)
VALUES ('5-203', '门锁坏了');
```

把第一条说得再清楚一点：

```sql
UPDATE repair
SET content = '水龙头一直滴水'
WHERE id = 1;
```

第二条不想留了：

```sql
DELETE FROM repair
WHERE id = 2;
```

再 `SELECT * FROM repair;`，现在应该只剩下第一条，内容已经变成“水龙头一直滴水”。

`WHERE id = 1` 是在说只找编号为 1 的那条。改和删的时候别把 `WHERE` 随手拿掉，不然动的就不只一条了。

<details>
<summary>完整的 <code>sql/第05周.sql</code></summary>

```sql
-- 先给这几周的报修找一个地方
CREATE DATABASE after_class DEFAULT CHARACTER SET utf8mb4;

USE after_class;

-- 里面先放一张空表
CREATE TABLE repair (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    room VARCHAR(20),
    content VARCHAR(200)
);

-- 加两条报修
INSERT INTO repair (room, content)
VALUES ('3-412', '水龙头漏水');

INSERT INTO repair (room, content)
VALUES ('5-203', '门锁坏了');

-- 看看刚才加进去的东西
SELECT * FROM repair;

-- 第一条报修说得再清楚一点
UPDATE repair
SET content = '水龙头一直滴水'
WHERE id = 1;

SELECT * FROM repair;

-- 第二条报修不要了
DELETE FROM repair
WHERE id = 2;

SELECT * FROM repair;
```
