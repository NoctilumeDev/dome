# 第零周：先把环境搭好

这套东西适合刚开始学的人。别只看，要自己动手改。哪怕改出了报错，也把自己改了什么、看到了什么，一起丢给 AI，问清楚到底是哪里错了，为什么会错，然后自己改回来。

新手不要怕错。对初学者来说，一次错误往往比一次顺利跑通更有意义，它会告诉你哪里还没想明白。

但错误本身也不是功劳。看见报错就让 AI 代改，改完还是不知道为什么，这种错什么也没留下，是真的没意义。

如果只想写一个永远不报错的程序，最稳的办法就是什么也别写。可那也什么都学不到。

这里也适合另一种人：语法学了一堆，术语背了不少，IDE 也会用，可真要从零做点东西，还是不知道第一步该往哪儿走。不是学得不够多，是那些东西还没有在脑子里连起来。

那就看看这 16 周，再加 4 周短学期实训，一个小东西是怎么一周一周长出来的。这里说的“世界观”不是什么大词，就是遇到一件不会的事，知道先做什么、怎么看结果，出了错又该怎么往下找。

如果你是后来从头开始，先按 [README 里的说明](../README.md#先拿对代码)拿到第一周的代码。笔记看最新版，代码用当周留下的标签。

先不说远了。电脑上准备好 JDK 17 和 Maven 3.6.3 或更高版本，项目也下载下来。

环境安装这里会告诉你需要什么，也会说到什么样算装好了。真容易卡住的地方，会点一下，但不会把每一次点击都写成手把手步骤。

不是故意为难。自己找教程、问 AI、看报错，再换一种新办法试试，这本来就是学习的一部分。这个过程应该由自己走，不能交给任何人或者工具。

遇到具体问题时，把操作系统、做到哪一步、具体报错告诉 AI，别只扔一句“运行不了”。

终端里试一下：

```bash
java -version
mvn -v
```

两条都能显示版本，且 Maven 显示的 Java 版本也是 17，就可以往第一周走了。

现在用不到 MySQL，也用不到 Node。AI 要是顺手列出半页安装清单，先让它停一下。

后面再让你运行 Maven 命令时，都在项目里放着 `pom.xml` 的那个文件夹执行。

准备好了，就去[第一周](第01周.md)。

等它启动后再刷新网页。光刷新网页不会让修改后的 Java 生效。
