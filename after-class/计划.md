# 先记着这 16 周，还有后面 4 周准备干什么

最后做一个小小的宿舍报修：东西坏了，报上来，处理，完成。

一个项目接着写。改动尽量只围着这次要弄懂的东西，让人看 diff 就知道多了什么。具体写到哪一步需要拆代码，到时候看实际情况。

每周只能有一个新的惊喜。第一周发现 Java 写的话能到浏览器里，第二周发现浏览器带来的名字能被 Java 接住。一次只陪着人弄懂这一点，别因为还有篇幅就再塞一件事。

第三周先看见结果就够了：返回 Java 里的报修信息，Spring 帮忙变成 JSON。Jackson 和 JSON 原理先留着。

第六到八周，SQL 直接写在 Mapper 的注解里，让人一眼能找到。先不用 XML、通用 Mapper、DTO、VO 和代码生成器。

第十四周只做 `POST /login`、`POST /logout`，用 `HttpSession` 记住登录，检查现在有没有登录。准备一个演示账号。JWT、刷新令牌、Spring Security、RBAC、注册、验证码、找回密码、OAuth 都不加。密码如何保存，到写这一周时给出必要说明，不扩成一门认证课。

第十五周让 AI 写一个 `src/main/resources/static/index.html`，HTML、CSS 和一点 `fetch()` 就够了。页面由 Spring Boot 提供，直接请求 `/repairs`。不装 Vue、React、Vite、Node，也不用 npm。

文件上传和 AI API 暂时没排。先把上面这些写明白。

短学期在第十六周的代码上接着做实验。第十七周不靠把按钮变灰来处理两个同时到达的请求，也不把内容碰巧相同的两次报修当成重复提交。第十八周加缓存是为了看看它会带来什么问题，不假装这个小系统已经慢得必须上缓存。

第十九周只发本地演示通知，不接真实短信、邮件。先把异步和排队的事情看见，再决定用什么。不要把内存里排了个队写成消息一定不会丢；它做不到的地方也照实留下来。Redis、RabbitMQ 等工具现在不预装。

写完先审，再提交、推到 GitHub。笔记的周次和 Git 提交不用一一对应，阶段清楚时再留标签。已有的 `after-class-week-01` 同时包含第零周的环境准备和第一周的代码。时间戳用实际时间。比较版本时只看 `after-class/`，别把其他作业的改动混进来。

每周留一页学习笔记。哪里看不懂，就借身边的事说一句；能自己看明白的地方，让代码说。环境准备放第零周，别占第一周的开场。别为了讲课制造问题，别为了凑周次拆类，也别顺手重构其他周的东西。

第一周末尾留个问题：名字怎么从浏览器送到 Java 里？先不写做法，让人有机会自己想一想、查一查。
