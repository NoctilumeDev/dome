# 宿舍管理系统毕业设计候选方案

## 一、课题名称

**高校学生宿舍管理系统（简化版）**

## 二、选题背景与目的

本课题面向高校宿舍日常管理场景，围绕“宿舍与床位管理、宿舍偏好推荐、入住退宿、报修、账单、公告通知、数据看板”等业务，搭建一个可运行的 Web 管理系统。  
设计目标是实现完整业务闭环，体现“数据建模、流程控制、前后端交互”能力，作为本科毕业设计候选方向进行功能验证。

## 三、技术栈与边界

### 采用技术

- 后端：`Spring Boot 2.7`、`Spring Data JPA`、`MySQL 8.0`
- 前端：`HTML + CSS + JavaScript`（原生）
- 部署：本地运行

### 本阶段边界（不做）

- 不做验证码登录
- 不加入课程演示不需要的额外中间件
- 宿舍推荐只使用固定评分规则，不自动审批或决定最终床位
- 主要用于本地演示和少量用户操作

## 四、总体需求与功能范围

### 1）用户模块（必须）

- 角色：管理员、宿舍管理员、学生
- 新生注册（固定注册为学生身份）
- 登录（用户名/密码）
- 基本权限控制：不同角色看到不同菜单与操作按钮

### 2）宿舍与床位管理

- 宿舍楼、楼层、宿舍号、宿舍特点、床位信息维护
- 床位状态：空闲 / 已占用 / 维修中

### 3）入住申请与分配

- 学生提交入住申请
- 学生选择宿舍氛围、作息、卫生和兴趣偏好，查看最多 3 个有空床的推荐宿舍
- 推荐结果只供参考，学生仍可自己选择意向宿舍
- 管理员或宿管审核（同意/拒绝）
- 审核通过后完成宿舍/床位分配

### 4）退宿流程

- 学生提交退宿申请（说明原因）
- 管理员或宿管审核（同意/拒绝）

### 5）维修报修

- 学生提交报修单
- 管理员或宿管受理并更新状态（待处理 / 处理中 / 已完成）

### 6）水电费/月度账单

- 管理员或宿管录入每月水费、电费和其他费用
- 系统自动合计应缴金额
- 学生查看本人账单并进行演示性缴费

### 7）公告与通知

- 全局公告或按楼栋公告
- 学生按角色查看

### 8）数据看板

- 每栋楼入住率
- 待处理报修数
- 本月退宿/入住申请统计

## 五、数据库设计（最小可行）

建议先用“够用即可、不过度设计”：

- `users`：用户信息、角色
- `building`：宿舍楼信息
- `floor`：楼层
- `dormitory`：宿舍信息（楼栋、楼层、编号、总床位、宿舍特点）
- `bed`：床位（宿舍关联、状态）
- `move_in_application`：入住申请、学生偏好和意向宿舍
- `move_out_application`：退宿申请
- `repair`：报修工单
- `bill`：月度账单
- `notice`：公告
- 关系：学生-床位-宿舍-楼层-楼栋一对多/多对一

## 六、开发任务分解与进度安排

> 适合一个月到两个月完成（可按周推进）

### 第 1 周：立项与设计

1. 完成题目、需求说明、页面与流程草图  
2. 明确表结构（先覆盖核心字段）  
3. 建立 Spring Boot 基础项目与目录结构  

### 第 2 周：核心数据层

1. 完成实体类（Entity）与 JPA 仓库  
2. 完成数据库脚本和初始化数据  
3. 实现基础 CRUD 接口（用户、宿舍、床位、公告）

### 第 3 周：流程功能

1. 完成入住/退宿流程接口与状态流转  
2. 完成报修流程接口  
3. 完成账单录入与展示接口  
4. 完成固定评分的宿舍偏好推荐  

### 第 4 周：前端页面与联调

1. 注册登录页、菜单页、宿舍管理页  
2. 学生端：偏好推荐、申请、报修、账单查看  
3. 管理端：维护宿舍特点、查看学生偏好、审核、分配、处理报修、发布公告  
4. 前后端联调与缺陷修复

### 第 5 周：看板与优化

1. 实现统计 API（入住率、待处理报修数）  
2. 前端报表展示  
3. 规范化前端样式、异常提示  

### 第 6 周：整理文档与答辩材料

1. 编写说明文档（需求、设计、实现、手动验收）  
2. 准备演示数据与演示流程  
3. 形成毕业设计答辩用 PPT/演示脚本

## 七、验收清单（答辩可展示）

1. 新生可注册学生账号，并使用该账号登录  
2. 登录后可按角色进入对应首页  
3. 宿舍与床位信息可增删改查  
4. 入住/退宿流程可走完整审批链路  
5. 学生选择偏好后可看到最多 3 个有空床的推荐宿舍，并可自行改选  
6. 管理员或宿管能在入住申请中看到学生偏好和意向宿舍  
7. 报修可创建、处理、完成  
8. 账单录入后可供学生查看  
9. 公告可发布和查看  
10. 看板能展示当前关键统计指标  
11. 关键按钮操作（注册、推荐、分配、腾退、审批、提交）能够显示处理中、成功或失败提示

### 7.1 页面端点击顺序清单（验收模板）

建议按以下清单执行演示：  
`页面端点击顺序闭环验收报告.md`  
文档内包含：  
- 按角色的按钮点击顺序（学生/宿舍管理员/管理员）  
- 每一步的预期提示  
- 每一步的通过条件和失败提示

## 八、论文/报告写作建议结构

1. 课题背景与意义  
2. 需求分析（功能需求、非功能需求）  
3. 系统设计（架构、数据库、流程图）

5. 功能验收（页面操作截图）  
6. 总结与展望（可说明页面体验和数据校验的后续改进）

## 十、运行说明（草稿）

1. 启动本地 MySQL  
2. 导入数据库脚本并初始化数据  
3. 启动 Spring Boot 后端服务  
4. 打开登录页面，可先演示新生注册，再用管理员、宿管和学生三类账号演示核心流程
