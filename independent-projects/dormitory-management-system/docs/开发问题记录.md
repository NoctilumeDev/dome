# 宿舍管理系统开发问题记录

这份文档只记录本项目实际遇到并处理过的问题，方便保留开发过程，也可供后续选题参考。项目采用 Spring Boot、JPA、MySQL 和原生 HTML/CSS/JavaScript，没有使用复杂的企业级组件。

## 一、MySQL 连接失败

### 现象

后端可以编译，但启动时提示 `Public Key Retrieval is not allowed`，系统无法连接 MySQL。

### 原因

MySQL 8 的登录认证方式与连接参数不匹配，原来的数据库地址缺少必要参数。

### 处理

在数据库连接地址中加入 `allowPublicKeyRetrieval=true`，并保留 UTF-8、时区和关闭本地 SSL 的参数。数据库账号和密码通过本机环境变量设置。

### 收获

“代码能编译”不代表“项目能启动”，启动失败时要先查看最靠近数据库连接位置的报错。

## 二、密码不能直接明文保存

### 现象

早期演示账号的密码直接保存在数据库中，查看数据表就能看到 `123456`。

### 处理

使用 BCrypt 保存密码摘要。新增用户时先处理密码再入库；旧数据第一次成功登录后，也会自动换成 BCrypt 摘要。

登录成功后使用普通 Session 保存当前用户编号，退出时清除 Session，没有再增加其他登录方案。

新生注册只收用户名、姓名和密码，后端把身份固定为学生，不能通过页面注册管理员或宿管。没有加入验证码、短信、邮箱等课程演示用不到的流程。

### 收获

即使是课程设计，也不应该把密码原样保存。这里只使用密码摘要工具和 Session，做法简单，自己也能解释清楚。

## 三、实体字段和数据库列名要一致

### 现象

给床位增加“同一宿舍床号不能重复”的限制后，启动时提示找不到 `bed_no` 列。

### 原因

Java 属性名是 `bedNo`，数据库列名是 `bed_no`，唯一约束使用的是数据库列名，但实体中没有明确标注。

### 处理

在床号字段上写明 `@Column(name = "bed_no")`，让实体、数据库脚本和唯一约束保持一致。

接口返回数据时使用简单的 `Map` 挑选页面需要的字段，不把整棵 JPA 关联对象直接返回给前端，避免循环引用和无关字段泄露。

### 收获

表字段、实体字段和页面字段最好逐一核对，遇到启动错误不能只看最后一行报错。

## 四、隐藏按钮不等于真正的权限控制

### 现象

如果只在页面上隐藏管理按钮，学生仍可能直接请求管理接口，或者在查询地址中填写别人的学生编号。

### 处理

- 前端根据管理员、宿管和学生三种角色显示对应区域。
- 后端每个写操作重新检查当前登录角色。
- 学生查询入住、退宿、报修和账单时，后端固定使用当前学生编号。
- 学生不能申请退掉别人的床位。
- 宿管查询用户时只返回学生，楼栋、楼层和宿舍基础数据仍由管理员维护。

### 收获

页面控制主要是为了不让用户看到无关按钮，真正的权限限制必须放在后端。

## 五、入住和退宿要防止重复操作

### 现象

同一个学生可能重复提交申请，也可能被重复分配床位；两名管理人员同时操作同一张空床时，也可能产生冲突。

### 处理

- 已经有床位的学生不能再次申请入住。
- 已有待审核申请时不能重复提交。
- 分配前检查学生是否已有床位、目标床位是否空闲。
- 数据库限制一个学生只能占用一张床。
- 退宿申请只能选择当前学生自己的床位。
- 审批退宿时再次确认学生仍住在该床位，再修改申请和床位状态。

### 收获

关键操作不能只相信页面当前显示的状态，保存前还要在后端再检查一次。

## 六、页面加载和提示要简单清楚

### 处理

- 首页使用 `Promise.allSettled` 加载各模块，一个次要接口失败时不让整个页面直接退出。
- 表格中的用户输入先进行 HTML 转义，避免输入内容破坏页面。
- 角色和状态统一显示为中文。
- 学生退宿、宿管分配床位和录入账单使用下拉框，不再要求手填数据库编号。
- 管理表单、入住退宿表单和数据卡片统一宽度、间距与控件排列，表格过宽时可横向查看。
- 静态文件地址增加简单版本号，避免浏览器一直使用旧的 JavaScript 文件。
- 提交按钮在处理中暂时禁用，成功或失败后显示明确提示。

## 七、项目核对方法

本项目采用手动核对：先确认 Maven 编译和服务启动，再分别使用管理员、宿管和学生账号操作页面，并查看关键接口的返回状态。

重点检查未登录访问、学生越权查询、退掉别人床位、重复申请和负数费用等异常情况。核对过程中尽量不批量新增或删除演示数据。

## 八、推荐功能要控制范围

宿舍偏好推荐只采用固定分数，不引入额外组件。学生选择氛围、作息、卫生和兴趣，系统把这些内容与宿舍特点进行比较，并结合空床数量推荐最多 3 个宿舍。

推荐结果必须说明匹配原因，只作为学生选择和管理人员审批时的参考，不能自动通过申请或替代管理人员决定床位。这样既能体现一点特色，又不会把课程项目做得过大。

## 九、总结

本项目的问题主要集中在数据库连接、字段对应、角色权限、业务重复操作、页面提示和推荐范围控制。解决这些问题已经足够体现从发现问题到完成修改的过程，不需要为了显得高级而加入与核心流程无关的额外组件。
