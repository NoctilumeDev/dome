1. 项目是做什么的

这是一个本地运行的高校宿舍管理系统。它把宿舍里的几件常见事情放到网页上完成：

宿舍资料

维护楼栋、楼层、宿舍和床位。

入住与退宿

学生可先查看宿舍推荐，再提交申请，由管理员或宿管处理。

报修与账单

学生报修、查看自己的水电费账单。

公告与看板

发布公告，并查看床位和申请数量。

先记住一句话：页面负责显示和点击，Java 后端负责判断和处理，MySQL 负责保存数据。

2. 先把项目运行起来

2.1 准备软件

  • JDK 11
  • Maven
  • MySQL 8.0

2.2 导入数据库

先启动 MySQL，然后在 demo 文件夹打开 PowerShell，执行：

cmd /c "mysql -h 127.0.0.1 -P 3306 -u root -proot < backend\sql\dorm_demo_mysql_full.sql"

项目默认数据库用户名和密码是 root / root。如果你的密码不同，修改：

backend\src\main\resources\application.properties
注意：数据库脚本会重新建立 dorm_demo 数据库。里面如果已经有需要保留的数据，先不要重复导入。

2.3 启动后端

cd backend
mvn spring-boot:run

看到程序正常启动后，浏览器打开：

http://localhost:8660/login.html

2.4 注册和登录

新生第一次使用时，可以在登录页展开注册区域，填写用户名、姓名和密码。注册身份固定为学生，完成后再使用新账号登录。

4. 页面数据从哪里来

以“打开床位列表”为例，程序按下面的顺序工作：

打开主页面 app.js 发出请求 DemoController 接收 BedRepository 查询 MySQL 返回数据 页面显示表格
  1. app.js 调用 loadBeds()。
  2. loadBeds() 请求 GET /api/beds。
  3. DemoController 中的 beds() 方法接到请求。
  4. BedRepository 从数据库读取床位。
  5. 后端把需要的字段整理成数据返回给页面。
  6. app.js 把这些数据拼成表格。
看其他功能时也用这条路线：页面函数 → 请求地址 → Controller 方法 → Repository → 数据表。

6. 顺着“入住申请”看一遍代码

这是项目里最完整的一条流程。先不要逐行看，先理解每一步发生了什么。

6.1 学生先查看宿舍推荐

  1. 学生选择氛围、作息、卫生和兴趣四项偏好。
  2. 页面向 POST /api/dormitories/recommend 发送偏好。
  3. 后端只检查当前有空床的宿舍，再按固定分数比较偏好与宿舍特点。
  4. 页面最多显示 3 个宿舍，并说明匹配内容和空床数量。
  5. 学生可以采用推荐，也可以在意向宿舍中改选其他宿舍。
推荐只帮助学生选择，不会自动通过申请，也不会直接决定最终床位。

6.2 学生提交

  1. 学生确认意向宿舍并填写原因。
  2. app.js 向 POST /api/move-in 发送数据。
  3. 后端确认当前用户是学生。
  4. 后端检查学生是否已有床位、是否已有待处理申请。
  5. 检查通过后，保存个人偏好、意向宿舍和一条状态为 PENDING 的入住申请。

6.3 管理员或宿管处理

  1. 管理人员先查看学生偏好和意向宿舍，再点击“通过”或“驳回”。
  2. 页面请求 PATCH /api/move-in/{id}/approve。
  3. 后端再次确认申请还处于待处理状态。
  4. 先找意向宿舍的空床，没有时再找其他空床。
  5. 床位改成“已占用”，并记录入住学生。
  6. 申请改成“已通过”，记录处理人和处理时间。
  7. 页面重新加载申请、床位和看板数据。

6.4 为什么不能只改申请状态

因为“申请通过”和“床位被占用”必须一起完成。只改申请不改床位，页面就会出现申请通过但学生没有床位的情况。

退宿流程正好相反：申请通过后，把原床位恢复成空闲，并清除入住学生。

8. 常见代码写法

@Entity

表示这个 Java 类要和数据库表对应。例如 Bed.java 对应床位表。

@Id

表示主键字段。项目里的主键都是自动增加的数字编号。

@ManyToOne

表示“多条数据属于同一条数据”。例如多个床位属于同一个宿舍。

@GetMapping、@PostMapping

给 Java 方法设置访问地址。一般来说，GET 用来查询，POST 用来新增，PUT 或 PATCH 用来修改，DELETE 用来删除。

Repository 方法

像 findByUsername、findByStudentId 这样的名字，JPA 会根据名称完成常见查询，不需要每次都手写 SQL。

Session

登录成功后，后端把用户编号放进 Session。以后页面继续访问接口时，后端就知道当前是谁。

BCrypt

数据库里不直接保存登录密码，而是保存处理后的密码摘要。注册和管理员新增用户时先处理密码，登录时再比较输入密码和摘要是否匹配。

固定评分推荐

推荐接口把学生偏好和宿舍特点逐项比较：氛围相同加 30 分，作息相同加 25 分，卫生相同加 20 分，兴趣相同加 10 分，空床数量加 5～15 分。最后按分数从高到低返回最多 3 个宿舍。

9. 建议的学习顺序

顺序要做的事做到什么程度
第一步运行项目，注册一个学生账号，再使用三个默认账号登录知道注册流程和不同角色页面有什么区别
第二步看 index.html 和 app.js能找到一个按钮对应的函数
第三步看 domain 和数据库脚本知道 Java 字段对应哪张表
第四步看 DemoController能按地址找到后端方法
第五步完整跟一次入住或报修流程能说出数据在哪一步发生变化
第六步按手动验收清单操作能独立完成一次完整演示

适合初学者的小练习

  • 修改登录页标题，重新打开页面观察变化。
  • 在 styles.css 中修改一个按钮颜色。
  • 在 app.js 中找到床位状态的中文显示位置。
  • 在数据库脚本中找到三个默认账号。
  • 从 loadBeds() 开始，按第 4 节的路线把床位查询走一遍。
  • 选择两组不同偏好，观察推荐顺序和推荐原因有什么变化。
每次只改一个小地方，运行后确认效果，再继续下一处。这样最容易知道问题出在哪里。

10. 常见启动问题

现象先检查什么
提示无法连接 MySQL确认 MySQL 服务已启动，账号密码与 application.properties 一致。
提示 Public Key Retrieval is not allowed确认数据库地址里保留了 allowPublicKeyRetrieval=true。
提示没有 dorm_demo 数据库重新确认数据库脚本是否成功执行。
8660 端口被占用关闭占用该端口的程序，或修改 server.port。
页面能打开但数据加载失败先看后端窗口有没有报错，再确认 MySQL 是否仍在运行。
修改页面后看不到变化使用浏览器强制刷新，再确认改的是 resources/static 下的文件。

11. 答辩时怎么介绍

问题一：项目用了什么技术？

后端使用 Java 11、Spring Boot 和 Spring Data JPA，数据库使用 MySQL 8.0，前端使用原生 HTML、CSS 和 JavaScript。

问题二：登录以后怎样识别用户？

登录成功后把用户编号保存在 Session 中，后面的请求通过这个编号查出当前用户。

问题三：怎样限制不同角色的操作？

前端根据角色隐藏无关按钮，后端在处理请求时再次检查角色。后端检查才是真正的权限限制。

问题四：入住申请通过后发生了什么？

后端找到空床位，把床位设为已占用并记录学生，同时把入住申请改成已通过。

问题五：为什么金额不用普通小数？

水费和电费使用 BigDecimal，可以避免普通小数计算产生精度偏差。

问题六：项目最需要保证什么？

学生只能查看和操作自己的数据；同一个学生不能重复入住；申请状态和床位状态要保持一致。

问题七：宿舍推荐会不会直接决定床位？

不会。它只按固定分数给学生提供参考，学生可以改选，管理员或宿管还要结合空床情况审批入住申请。

  • 我能解释登录、入住、退宿和报修的基本流程。
